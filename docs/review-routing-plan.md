# Selective native/workspace review plan

The controller should choose a review strategy for the deciding work. Native and
workspace are complementary execution paths. A whole-package workspace result
does not decide which path every rule should use. This corrects the overly broad
next-step interpretation of [AI](experiments/review-workspace-mixed-fallback-results.md),
without changing its results or reopening its budget.

Current consolidation: [new knowledge and decisions](review-knowledge.md).
The [fresh AL packet comparison](experiments/review-hybrid-packet-plan.md) separates
logical shared investigations from context placement. Explicit `packet_batch`
can retain independent local claims beside a workspace subgroup without adding
native fragments or assuming shared authorization. It replaces a fragmented
trial design, while preserving AJ/AK's original results and budget safeguards.

## Initial routing policy

| Deciding work | Initial path | What changes the route or scope |
| --- | --- | --- |
| Complete SQL construction/binding and relevant input transformations | Native batch | Settle grammar injection locally. A separately selected authorization or credential claim can need a relationship investigation; do not make that a prerequisite for every SQL verdict. |
| Cookie flags, local parser API/configuration, other self-contained API uses | Native batch | Preserve separate exposure/configuration conditions. Escalate only an actual unresolved dependency or caller relationship, not the rule name. |
| Multiple claims on the same handler with a shared identity/check-to-effect chain, such as deluxe branches | Shared workspace investigation | Share the implementation evidence and qualified facts; close each selector/effect independently. Split incompatible callers rather than transfer a verdict. |
| Shared helper/service with distinct caller configuration, tokens or policy | Workspace with a shared deciding question and per-caller checks | Reuse the exact conditional fact only where its binding and conditions apply. Local safe/unsafe callers can close while another remains unresolved. |
| One authorization/credential/workflow claim whose decisive relationship spans reads and needs partial state | Targeted workspace investigation | State should retain the check, selector, effect and exact remaining question. A simple complete owner-selector chain can still close natively. Complexity alone is not evidence of savings. |
| AI's conditional NoSQL case | Native initially | Native completed the deciding investigation in four calls versus six. A workspace navigation correction is a separate targeted candidate, not a reason to change all database review. |
| Unrelated claims with no demonstrated shared deciding work | Native batching | Keep the ordinary maximum 20; do not create a workspace conversation for each unsupported anchor. |
| A genuinely unavailable deciding fact | Preserve precise uncertainty in the current path | Record what could change the decision and stop that investigation. Creating another workspace or searching again does not make an unavailable implementation available. |

These are inspection defaults, not a released automatic dispatcher. Rule family
supplies an initial strategy; actual construction,
shared dependencies and caller compatibility determine exceptions. In particular,
"SQL native, everything else workspace" is still too coarse: local cookie/YAML
work already closes efficiently in native batches, while shared authorization
work has different needs.

## Evidence behind the split

- [L2 confirmation](experiments/review-workspace-confirmation-results.md): the SQL
  pair closes in one grouped turn versus two singleton turns; deluxe in two versus
  six. Both are uncapped. Both arms here use workspace, so this establishes useful
  work formation, not a measured native-versus-workspace SQL win. Native is the
  practical initial SQL choice because it already batches local work without the
  additional workspace protocol.
- [AA policy contrast](experiments/review-workspace-policy-contrast-results.md):
  workspace retains a conditional helper fact, closes safe/unsafe local callers
  separately and continues with only the external case active. Preserve this
  concrete state behavior. Its external fixture and differing activation reads
  prevent an equal-assurance whole-package efficiency claim.
- [AI](experiments/review-workspace-mixed-fallback-results.md): native already
  shares the cookie/YAML work. NoSQL navigation favors native in this run.
  Resource fallback takes fewer workspace calls, but native reads a deeper
  role-to-credential chain; do not optimize by dropping that proof.
- [Q2 work formation](experiments/review-work-formation-results.md): related
  logout callers can share a service question while retaining distinct token
  handling. Its assisted AI proposal is not evidence that an extra planning pass
  pays for itself on every batch.

All are development evidence with documented qualifications. None establishes
universal routing by category or independent human accuracy.

## Implementation order

1. **Make route selection inspectable before changing dispatch.** Use saved
   inventories, the existing planner's `local_sql`/operation proposals and source
   bindings. Produce exact claim coverage, proposed execution path, the deciding
   question, any shared implementation/fact and the reason for separation.
   Existing metadata should settle obvious local batches. Manually review
   ambiguous relationships in this first slice and count that work; do not hide
   a full investigation in the router. Implemented/checked in AJ: CLI output also
   exposes split native bundles, proposed unit counts and groups already fitting
   one native packet. Shared-service selection remains explicit, not automatic.
2. **Add pre-dispatch selection to the experimental comparison controller.**
   Dispatch each selected claim through one path and retain the original native
   bundle/result mapping. Native lanes keep ordinary batching. Workspace lanes
   use existing questions, scoped propositions, applicability and review-package
   export. Do not add a new fact engine, general test preloader or mandatory AI
   planner. Keep the production default unchanged until the routing slice is
   checked. Bind the inspector artifact and complete original-result mapping.
   Charge fragments and cross-bundle shared groups to their connected original
   bundle allowances; creating units must not multiply paid budgets. Implemented
   and exercised in AK; see the [dispatcher usage](review-hybrid.md). Native uses
   ordinary worker validation-only mode, and treatment performs no admission.
3. **Check the mixed package, rather than requiring one engine to win it all.**
   Compare ordinary native maximum-20 review with the proposed hybrid policy.
   Include SQL/native local controls, shared handler/effect work, differently
   configured callers and a precise unavailable-fact control. Include a simple
   authorization case that should remain native, so the router cannot pass by
   sending every authorization anchor to workspace. Freeze selection/source,
   per-investigation allowances and evaluator proof requirements before calls.
   Count route preparation, both execution lanes and package assembly together.
   AL completes the first such live comparison, with no same-model speed win and
   the wrapper proof qualification above. Do not repeat the successful packet
   siblings to chase a favorable aggregate.
4. **Fix only the failing route or boundary.** The NoSQL evidence-navigation
   question remains useful for a targeted offline diagnostic; it is not a global
   prerequisite for the hybrid slice. Qualification loss, stale facts or missing
   credential proof require their own affected-case correction. Retain successful
   native and workspace lanes when another lane is mixed.

First version is pre-dispatch routing. Automatic mid-review handoff is deferred:
the current native final answer is not a complete transferable investigation
checkpoint. A future handoff must carry actual source/lookup receipts, supported
facts with conditions, the unresolved question and paid accounting. It must not
start a second full review of already settled claims or silently trust generated
notes as facts. Do not claim that this handoff is implemented.

An AI planning pass is optional for an ambiguous cluster only when metadata and
existing source bindings cannot establish the proposed sharing. It proposes work,
not verdicts; its entire lookup/model/verification cost belongs to the package.
First test whether that assistance is necessary rather than deploying a paid
classification conversation per candidate.

## Continue, narrow or stop

- Continue a route when it preserves the required mechanism, qualifications and
  caller proof, and avoids substantive repeated work or improves complete-package
  time after preparation. More input by itself is neither success nor failure.
- If native already settles a local batch in one turn, keep that route unless a
  concrete unmet requirement justifies a different path. A shorter packet is not
  enough.
- If a workspace case needs unique investigation but produces no reusable fact,
  judge its state/partial-closure value and total cost separately from sharing.
  Narrow that route if the added protocol does not help; do not discard working
  shared investigations elsewhere.
- Reject unsafe merges, missing supported mechanisms, wrong dismissals and
  unsupported severity in the affected route. Preserve all spend and evidence;
  correct and separately freeze the affected slice. Do not reset successful lanes
  or silently repair a paid run.
- Stop router expansion if selecting the route repeats the whole review or an
  extra planner costs more work without a useful package benefit. Prefer direct
  rule/locality defaults with explicit exceptions.

No paid run is dispatched by this document. AI's retired slots and old studies
remain closed. Full-app review still needs a successful mixed hybrid slice and
separate confirmation; it does not require workspace to beat native on SQL.
