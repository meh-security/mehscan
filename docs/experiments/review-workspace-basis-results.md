## Concrete information loss

Inspection of S's actual native/workspace packets exposed a second package
difference beyond the already corrected API policy. Ordinary native review received
the operand facts, remaining checks, nearby implementation locations and observed/
unresolved decision facts from its native card. Workspace retained only the selected
property, anchor line, capability and rule. For the SDK claim this discarded the
explicit local-callable context and remaining caller-authority/branch/effect leads.
Equal source windows therefore did not mean equal evidence-map information.

Separately, workspace hid answered questions from replacement contexts. Unless the
model also saved a proposition, an intermediate conclusion and its scope disappeared
while another relationship for that claim was still open. This made the model's
available state poorer than the workspace's stored history. Reopening an answered
question also failed to invalidate its previously drafted consumers.

## Implementation

The bridge now retains a projection of each active native card: exact relationship,
anchor/operand facts, observed and open decision facts, nearby/application/frontend
locations and truncation. Related native contracts are delivered once for the
active claims. This is a selected projection, not a claim of full native sweep or
prompt parity. Scanner observations remain leads rather than verified authority or
a mandatory investigation checklist.

The complete native bundle catalog has a digest included in the SQLite runtime
binding. Changing its facts rejects preparation before dispatch; changing the
catalog and its claimed digest together still mismatches the stored binding.
Older experimental workspaces require fresh preparation, not a silent migration.

For an active claim, an answered question retains its latest conclusion and cited
source in the next provider packet, marked `reviewer_interpretation`. Complete
attempt/lookup history remains in storage; resolved lookup history is not replayed.
The cited source stays fresh even when a focus update omits it. The note remains
scoped to that question's exact claim IDs; it is not automatically transferred to
a different caller. Retired claims do not accumulate notes in subsequent contexts.
Existing propositions/applicability remain available for explicit cross-work reuse.

Changing an answer invalidates its drafted consumers, including a previously
pending claim whose decisive missing fact is now supplied. A new deciding lookup
reopens an answered question and retains the prior spending. Bundle closure cannot
use an older settled verdict while a deciding question remains open. The reviewer
must still assess whether the supplied evidence actually answers the question.

No new model fields, mandatory progress actions, typed closure subsystem, prompt
paragraph, caller enumeration or SDK-specific instruction was added. The existing
question/answer/proposition actions carry the distinction between a known local
mechanism and an open application binding.
