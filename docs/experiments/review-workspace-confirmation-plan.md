# Fixed-controller confirmation

Status: [completed results](review-workspace-confirmation-results.md). The pair
used 31 versus 21 calls with no controller errors. The basket group reached its
six-call cap, so its contribution is budget-confounded; SQL/deluxe provide the
clear uncapped benefit. The design below is preserved as the executed plan.

Compare complete-operation singletons with concrete shared investigations on
the same twelve claims as the [expanded comparison](review-workspace-expanded-results.md).
The earlier 35/36/21/29-call results include controller repairs. This fresh pair
tests whether the grouping benefit survives under the corrected controller.

`scripts/review_workspace_comparison.py` prepares and runs the comparison.
`prepare` accepts the prior run through `--reference`, plus `--output`, `--private`,
`--scanner`, `--provider-config` and `--provider-executable`. `run --root RUN`
executes the frozen controller serially with separate native/private stores.

Both arms receive identical source profiles per claim; groups receive their
union. The preparer extracts only the first singleton session's raw source,
file hashes and locator limitations, checks it against the earlier pre-model
preparation receipt, and verifies the group union against that group's earlier
preparation receipt. It captures the same bytes from the current pinned snapshot.
No old proposition, answer, verdict, guidance, seed notebook or evaluator label
enters the new workspace. New native state, claims, work, runtime bindings and
provider sessions are created. Controller/package/config hashes are frozen
before dispatch, together with the Git commit and source parity receipts.

This confirmation reuses fixed source preparation rather than rerunning reference
locators. Their original nominal preparation query units remain charged against
the work allowance; they are identified as fixed-profile units and never reported
as new native locator calls. Native preparation and elapsed time are measured.
An unused generic-pilot singleton preparation is retained as preparation history;
it makes no model calls and supplies no learned state to the grouped arm.

The model, effort, source snapshot, rule questions and group membership stay the
same. There is no new dependency contract, fact seed, planner pass or instruction
tuning. Native bundle defaults remain unchanged; this experiment uses singleton
native bundles and separate verdicts even within a grouped investigation.

The ceiling is six paid calls per work item, 48 per arm, 96 overall; 24 query
units per work including fixed preparation, 200 units and 4 MiB per arm; 2,400
seconds active per arm and a 6,000-second whole-run deadline after preparation.
The existing generous 3M input / 100K output safety ceilings remain; token/output
reductions are not acceptance gates. Unknown usage stops dispatch in the affected
arm. Known case failures preserve costs and permit independent cases to continue.
No case is silently dropped or converted to a negative.

Do not edit the controller or append paid repair runs inside this comparison.
If it fails, report incomplete coverage and the defect. Preserve every paid turn.
If it completes, audit the whole package: SQL mechanisms and TOTP qualification,
identity-to-effect ownership controls, deluxe payment bypass placement, file/YAML
controls, basket/generated effect uncertainty and password reauthentication scope.
Report time, turns, repeated source and actual counters by family. Source-schema
validation alone is not security-quality equivalence. One paired development
run is not a statistical estimate or held-out benchmark.

The next dependency-reference, interactive CLI and compact AI-grouping work
remains as described in the expanded results. This confirmation does not authorize
an automatic full-app rerun or erase earlier experiment costs.
