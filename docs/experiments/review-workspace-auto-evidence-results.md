# Automatic registration-helper evidence

The planner now supports opt-in `--prepare-helpers`. It follows direct relative
imports for explicit registration references and supplies bounded definition,
import and call-site source before review. Definitions can be reused across work
items while caller questions and native verdicts stay separate. Grouping and
helper delivery apply in one atomic transaction. The feature is experimental;
ordinary scheduling and native bundle defaults are unchanged.

This milestone closes the hand-written target-list gap for those registration
references. It does not establish helper semantics, runtime binding, dependency
contracts, complete caller discovery or security correctness. A function called
`owner` is not presumed to enforce ownership. Wrapper source is presented for
assessment, not treated as proof of transparent dispatch.

## Correction to the next experiment

Do not rerun the earlier helper-only memory comparison simply because selection
is now automatic. That comparison already showed fewer helper queries without
fewer deciding turns. This implementation reduces manual preparation and makes
sharing concrete; it does not change the unresolved dependency effect.

The next decisive live package should establish a provenance-qualified deciding
contract or independently assessed operation mechanism, then compare complete
packages with matched groups and aggregate allowances. Keep a declared range,
resolved version, reference implementation and observed runtime effect distinct.
Do not feed evaluator-only source into a reviewer arm implicitly. Preserve
supported mechanisms and actionable uncertainty, including incompatible callers.
Stop on an unsafe transferred conclusion; inspect actual deciding turns and
total usage/time before expanding. No full-app run is justified by this offline
milestone alone.
