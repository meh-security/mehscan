## Balanced assessment and decisions

For each claim, record the supported mechanism or scoped negative, deciding
evidence, relevant caller/input conditions, unresolved prerequisite and severity
basis. Distinguish unsupported findings/dismissals from qualified uncertainty and
additional unclassified leads. Pay particular attention to:

- CSRF: accepted cookie identity and an owner selector do not settle cross-origin
  request applicability. Preserve cookie-delivery/request-construction conditions
  and effective origin/request-token controls where unestablished.
- Redirects: assess request influence on each configured `BASE_PATH + /profile`
  target. A scoped redirect negative does not certify the rest of the handler.
- Duplicate-key basket mutation: preserve raw-body parsing, first checked versus
  last used selector and accepted-caller/quantity checks.
- Native relationship peers: authentication or inserted `UserId` is not an owner
  predicate on an id-only basket lookup; dynamic requested fields differ from a
  default response allowlist; password/setup checks differ from TOTP encryption.
- Generated resources and coupon policy: prove the actual write/enforcement
  contract or retain the exact conditional mechanism. Do not invent missing
  generator policy, guaranteed LLM invocation or universal coupon redemption.

Trace lookups as requested deciding question → returned evidence → remaining
question → decision. Record repeated source/reconstruction and whether a fact
helps later compatible consumers, rather than inferring memory benefits from the
existence of a proposition. Measure actual calls, input/cached/output tokens, model
time, active/controller time, preparation and assembly; input volume alone is not
a success gate. Assisted audit/selection time that is not completely measured
remains an explicit additional cost.

Continue a useful route when its proof/state benefit or reduced repeated work
justifies its cost. If co-located peers cause trouble, narrow that placement while
retaining useful URL-handler sharing. If a native peer regresses after splitting,
correct that context boundary rather than abandoning workspace. If verdicts agree
but assurance differs, retain the distinction. No all-or-nothing win requirement
and no whole-application conclusion from this slice.
