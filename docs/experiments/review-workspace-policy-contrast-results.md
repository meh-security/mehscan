## Source mechanisms and retained progress

**Safe instance — `observation-review-97907bbd824f5b75`.** All arms inspect the
actual local factory and its fresh instance in `page-one.js`. The factory creates
a private hooks array per invocation, escapes `&`, `<`, `>`, double and single
quotes, then applies that instance's hooks. This caller registers none. The shared
adapter delegates without decoding or changing the returned text before the exact
HTML-content sink. The scoped `not_issue` is supported; a different instance's
hook does not mutate this one.

**Post-control hook — `observation-review-1acf5176344471f2`.** All arms inspect
`input.js`, the local factory/adapter and `page-two.js`. A decoded URL `action`
value is inserted into an image's inline event handler by a hook **after** the
content escaping pass; there is no later control before the selected `innerHTML`.
The source weakness is supported under ordinary module activation/browser-handler
conditions. All rate it high severity. Native additionally reads the mounted
`two.html`; workspace reasons from the local source chain. This is no executed
exploit or assurance about every delivery/deployment path.

Both workspace arms publish a shared proposition with explicit qualifications:
the base escaping protects HTML content only if later hooks do not introduce
markup, and it establishes no behavior for an external policy. Their per-caller
decisions apply that condition differently. Shared investigation can therefore
reuse the implementation fact across configuration variants while keeping closure
caller-specific; compatibility is a property of the fact being reused, not an
automatic shared verdict for every caller.

Both read the shared factory/adapter and URL reader once. Native similarly reuses

## Why the external runtime-uncertainty control is defective

All arms keep `observation-review-a2cbd2fbdc1fdeeb` as `needs_review`, naming the
missing external policy contract instead of transferring local safety. That is
useful contract reasoning, but the supplied `three.html` directly loads a browser
module with an unmapped bare package import. Literal browser loading fails before
the selected sink evaluates. The normative resolution rule is in the
[HTML Standard](https://html.spec.whatwg.org/multipage/webappapis.html#resolve-a-module-specifier).

Thus the fixture conflates an unknown library contract under an additional binding
with an affirmatively inapplicable literal page. Its frozen expected runtime
uncertainty cannot score that distinction. Native reads `three.html` but does not
close the literal binding; workspace does not inspect the HTML. Agreement is not
ground truth. Preserve original expectations and verdicts; do not silently rescore
this as a model pass, a proven wrong safety dismissal or an active vulnerability.
This defect should have been caught in the pre-dispatch source audit.
