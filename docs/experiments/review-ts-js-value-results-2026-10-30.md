## JavaScript binding coverage corrected

The source audit found a MongoDB `$where` construction behind an exported
identifier-bound function-expression constructor. The existing query analysis
could summarize its executable selector, but module metadata collected instance
methods only from function declarations. Consequently the imported constructor's
caller binding did not produce a first-class database-query claim. The original
reviewer had retained this mechanism as an unreviewed neighbor lead; it was not
absent from every review artifact.

`node_modules.rs` now recognizes ordinary identifier-bound function-expression
constructors, preserving instance/static separation, lexical `this` ownership
and reassignment guards. Arrow functions, async declarations/expressions and
unrelated nested assignments do not gain constructor contracts. The fix changes
binding coverage, not the taint rule or Value policy. Generic reduced fixtures
reproduce the missing query before the fix and pass afterward; all 17 relevant
Rust tests pass, including six negative constructor subcases.

## Evaluation-order regression caught by controls

The extension retains the benefits issue and own-profile negative but wrongly
dismisses `observation-review-d5977d09ff6b14b5`. It reads the request-controlled
`eval` calls, yet treats them solely as a separate code-injection lead. In the
actual handler, direct evaluation occurs **before** reading `req.session.userId`;
an expression can change that ID and return valid numeric values before the
selected contribution update. The earlier authority check therefore does not
establish the identity used at the effect. Source-valid finalization did not
catch this semantic failure.

The same bounded shared guidance now says to track changes to principal,
authorization state and selected object across the check/effect evaluation
order. A different weakness category does not make a causal earlier operation
irrelevant. Conversely, a mutation does not automatically change an independently
captured value. No app names, expected outcomes or contract fields were added.

One prompt-only retest, with identical initial source for the three NodeGoat
controls, returns **two issues / one negative**: the contribution identity
mechanism is recovered and both other controls retain their decisions. Two
HedgeDoc credential-feasibility controls remain **needs_review**, exhausting
their original six-call allowance without promoting an unestablished principal
combination. These two were a focused bundle with ordinary source, not the
original eight-claim bundle or a replay of prepared workspace evidence.

This last test costs 10 calls / $0.151776 / 56.315 s across the two concurrent
apps. It supports the clarification on these cases, not a guarantee against
future model mistakes. Both the wrong negative and its replacement remain in
