# Dependency-source navigation comparison — 2026-10-30

**Result:** implementation and offline navigation gates pass. The live comparison
finishes with **120/144 assessments finalized, 55 completed pairs, 13 verdict
disagreements and eight HTTP 403 attempts without usage receipts**. Keep the
navigation capability opt-in. Useful local evidence improved, but the changed-source
paired subset costs more and some differences merely move the closure boundary.
No global rollout, precision estimate or efficiency win follows from this test.

## Question and implementation

The CT experiment expanded controller context but repeatedly left the invoked
service, JWT strategy and permission implementation unread. The next test asks
whether bounded, source-bound navigation improves the final review package.
It does not change the reviewer prompt, bundle grouping or native/workspace
routing, and does not turn every claim into exhaustive caller discovery.

`investigate import-targets` reads actual JS/TS import declarations and uses
the existing native module resolver. The opt-in source-profile builder follows
imports relevant to the anchored operation, declared constructor dependencies,
and literal Nest Passport guard/strategy registration keys, including aliases.
It can include the source module importing a matching strategy declaration.
These are evidence candidates: exported-member identity, DI overrides, active
module registration and compatible caller context remain the reviewer's work.
Dynamic keys, unresolved modules and duplicate registrations are not guessed.
No application names, claim IDs or expected answers affect navigation.

Bounds remain eight windows and 64 KiB per bundle, with at most 400 lines and
16 KiB per window. Navigation caches source/query results within preparation,
with an 80-query bound per work package. It does not cache security conclusions.
The existing parser limitations remain reported lookup failures.

## Gates and stopping rules

1. Before inference: native navigation regressions and source-profile tests
   pass; all selected IDs/bundles/contracts agree; every source window matches
   its frozen file; inspect whether real service/strategy source is delivered.
   If preparation only adds irrelevant bytes or loses core source, correct it
   offline before paying for the run.
2. After inference: reconcile every offered attempt, receipt, cached input,
   output, wall time and API-equivalent price. Unknown usage stays unknown.
   A failed bundle does not stop independent work; no silent retry or budget
   reset. The earlier CT 15 unknown attempts remain in their original ledger.
3. Audit every changed decision and sensitive unchanged controls against source.
   Count supported mechanism retention, defensible local negatives, precise
   uncertainty and execution completion. Source validation alone is not quality.
4. Keep the feature opt-in if results are mixed. Retain useful dependency paths
   and surgically address repeated omissions. Do not add broad recursive
   discovery, more prompts or a universal second reviewer merely to improve a
   completion count. Distinguish implementation gaps from genuine external
   assumptions and provider failures.
5. Freeze this change and broaden testing only if useful quality gains survive
   source audit without sacrificing controls and package price remains sensible.
   No precise percentage-saving or precision claim from one stochastic sample.

Preparation and coordinator/source-audit effort are additional work, outside
provider receipts. Record preparation time separately. No upstream admission or
default rollout is authorized by this experiment.

## Completed preparation and execution

The native module-navigation regression and nine source-builder/dependency tests
pass. Tests cover same-name modules, aliases, missing imports, duplicate literal
registrations, dynamic keys, failed lookups, ambiguity, out-of-scope source and
decorator-starting anchors. The real-source preflight caught the latter: an anchor
can begin before the method AST span, so constructor dependencies were initially
missed. Enclosing-class recovery fixes that, and invoked dependencies now precede
passive type imports. No paid call used the defective preflight.

controller regression run completes **74 tests, one skipped, no failures**

review wall times below and incurs no reviewer-provider spend. `git diff --check`
passes. Changes remain uncommitted; unrelated identity work is untouched.

identical source. The new profiles contain 69 windows across all five apps.
Preparation takes **9.551 seconds** for the existing builder and **40.768 seconds**

initial packets. The trace records 113 window-limit omissions, eight unresolved

## Corrected direction and milestones

1. **Complete: reusable navigation primitive and controlled larger comparison.**
   Keep explicit import resolution and source hashes. Keep native local review
   and selective shared workspaces. Preserve the mixed evidence and all costs.
2. **Next: deliver a small dependency chain for a stated deciding question.**
   Source-window scheduling should keep a guard and its strategy, or a called
   member and its re-export/provider evidence, together. The current global
   bundle allowance admits unrelated source while omitting discovered dependencies.
   Add bounded named/star re-export navigation with ambiguity, cycles, conditional
   exports, absent-build and caller counterexamples. Expose exact navigation for
   selective lookups instead of preloading every possible dependency. No recursive
   application investigation and no verdict reuse merely because names match.
3. **Next: preserve closure scope in the review package.** A local negative about
   task creation or direct response handling must coexist with an unresolved
   downstream effect when that effect belongs to the selected question. Likewise,
   unavailable optional code must not invalidate a proved base-path relationship.
   Use the saved disagreement set as an offline acceptance corpus before changing
   prompts or adding another paid reviewer. Facts need source hashes, caller and
   predicate scope; related claims keep separate verdicts.
4. **Hold wider paid expansion.** The repeated provider 403 failure is still a
   separate operational limit. Preserve error category and attempt lineage;
   diagnose through supported provider operation, not prompt or transport bypasses.
   Any later recovery must retain old unknown costs. After offline scope/delivery
   checks pass and provider operation is usable, test a representative larger slice
   including the unchanged Python mismatch mechanism and clean local controls.
   Do not buy another full-app comparison merely to chase a cleaner aggregate.

This turn establishes useful implementation and several better proof paths, not
a balanced unattended default. Keep the feature opt-in; freeze further blanket
preparation/prompt changes while correcting these concrete delivery and scope gaps.
