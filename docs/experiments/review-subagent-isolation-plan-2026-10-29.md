## Question and scope

Does a same-model isolated implementation researcher improve the quality and
complete-package price of review, compared with reviewers investigating directly?
This tests context isolation plus evidence handoff, not a different cheaper helper
model, instruction trimming, recursive delegation or an independent second opinion.

Preserve three original native bundle memberships: nine database claims, nine
framework authorization claims and four authentication lifecycle claims. All
22 claims, including SQL and authorization peers, are reviewed in every arm.
Do not split a useful native batch into singleton controls to favor delegation.

- JWT family: one implementation researcher supplies two consumer bundles.
  Investigate declared root/middleware bindings, expiry, decode and verifier
  semantics; each consumer still determines caller applicability and effects.
- MarsDB family: one researcher supplies one existing nine-claim bundle. Direct
  review already shares investigation within this bundle; delegation can add
  pure overhead. Retain unrelated SQL peers in both alternatives.

Four arms: Terra direct, Terra helper, Sol direct, Sol helper. Run arms concurrently
in isolated states. Within each arm, JWT then MarsDB; JWT consumers retain the
same order. No cross-arm notes or judgments. Each helper uses its consumer's model
and effort. Charge helper production entirely to its own arm, once per family.

## Source and protocol boundary

Use the pinned 1,285-file Juice source and saved primary vendor snapshots. Original
source IDs/questions and bundle membership are retained. Initial entry windows
are identically prepared from anchors in both alternatives. All roles have the
same read/search/list broker and available source universe, including vendor
versions. Shared implementation questions are visible in direct arms too.

This is a new, source-only diagnostic harness with a simple common contract;
it is not the native admission pipeline or an exact replay of BG prompts. The
study cannot attribute changes versus BG to subagents. Only fresh within-model
direct/helper comparisons isolate the treatment. No target application or vendor
code is executed or installed. Model access remains restricted by the existing
launcher; the controller schedules helpers, with no autonomous delegation.

Helpers return bounded facts, conditions, limitations and inspected source ranges.
Consumers receive those notes plus original supporting excerpts, never exploration
history. They may reopen source and disagree. Direct reviewers have the same
source access. Evaluator conclusions, old model verdicts and the source-quality
audit are not provider inputs. Vendor snapshots establish version-bound static
semantics, not deployed dependency resolution.

## Finite execution and accounting

Each session has up to eight calls; each model/mode/family shares at most 24 calls,
100 source queries and 1 MiB of returned query JSON. Helper source handoff is at
most 16 ranges/64 KiB. A read is at most 400 lines/64 KiB. Calls have a 1,800-second
timeout; no three-minute, 3M-input or aggregate-time cutoff. These are safety
ceilings, not expected spend. Direct topology reaches at most 24 calls per arm;
helper topology at most 40. Report any cap censoring rather than treating it as
semantic failure or savings. No budget refills or automatic paid retries.

Record every call and cumulative-counter delta, prompts, returned source,
handoffs, final evidence and timing. Unknown usage stops the affected arm;
other independent arms can complete. Preserve failures and costs. Keep frozen
inputs separate from mutable progress. All old studies and retired allowances

Full comparison includes producer plus consumers, preparation, source retrieval,
provider time, arm elapsed time and remaining correction work. Reused archived
vendor acquisition has unmeasured historical human time: disclose it, do not call
production preparation free. This diagnostic has no native admissions.
