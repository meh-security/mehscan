## Deciding lookups and evaluator checks

Neither workspace arm requests a lookup. Shared propositions are published and
used in the first response; no later context reuses them, and no settled consumer
is offered or reconfirmed. The read-only AU audit reproduces both one-turn states
without receipt-chain gaps and leaves all eighteen files in each workspace
unchanged. There is no new evidence for a mandatory notebook or memory subsystem.

Native lookups pursue credential production and effective inherited permissions,
rather than repeating an identical investigation per claim. Two navigation costs
are visible:

- Both native models request a named `authenticate` definition in a file with an
  anonymous default export, then obtain its source after the no-match result.
  No named declaration is invented. This is an import/lookup shape mismatch.
- Sol native's third response requests four queries, including a directory-valued
  definition path, `api/src/permissions`. The whole batch is rejected before any
  lookup executes: **seven charged query units, zero native queries**. A pure
  validation replay reproduces `file_filter_is_directory`. Later requests adapt;
  there is no identical repair loop. Definition lookup accepts a file, unlike the
  separate directory-capable reference API. Keep the actual cost; do not infer
  a counterfactual number of saved calls or widen that tool's scope silently.
