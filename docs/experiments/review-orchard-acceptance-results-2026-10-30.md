## Gate decision and practical direction

**Passed:** all 30 native claims source-validate without execution failure; exact source/proof guards remain; all 58 paid attempts are receipted; frozen runtime/source hashes match; completed filesystem work survives the owner failure; no native admissions or target execution occur.

**Not passed:** clean unattended completion and semantic promotion without source audit. One last-turn auxiliary reference still requires manual recovery. Two new promotions need source/authority correction. Extra prepared source alone does not prevent overextending a local contract review into application discovery.

Keep the balanced operating profile: cached Terra native for the base and complete local contracts, question-driven workspace for actual shared/complex relationships, and selective source/flow review before promoting findings. Do not discard workspace because one group failed, or generalize its filesystem success to every rule. Do not call the cheapest raw verdict set the final reviewed package.

Freeze comparative experimentation here. The next narrow engineering task is an explicit **candidate-only validation/preview path** for already paid decisions when auxiliary actions fail. It must verify receipt, immutable reply, claim/context membership, actual inspected citations and current source; preserve failed actions and unanswered state; and never automatically admit a finding. The saved `source132` reply is a concrete offline regression. Reject stale inputs, unseen citations, foreign IDs and changed text. No full-app rerun is needed to design or test that path.

Separately, carry the deciding boundary into the chosen review prompt/question. The filesystem follow-up succeeded with a local API-boundary question; native had the same core helper source but pursued HTTP callers. Clarify local guarantees versus deployed authority in existing category/question guidance, rather than adding a universal instruction inventory or another mode tournament.
