# Fresh application results: PyGoat — 2026-10-29

The selected workflow handled a fresh Python/Django/Flask application for **$1.5673714 in measured reviewer API equivalents**, including a selective workspace follow-up. Keep Terra medium with stable native schemas as the first pass. The useful next correction is evidence continuity and careful impact classification, not another full model tournament.

The experiment also exposed a real remaining weakness: one mixed HTML bundle exhausted its lookup allowance and left ordinary outputs unresolved even though relevant implementation source was already available elsewhere. A small follow-up closed five such uncertainties. Its other two proposed findings demonstrated a title-setting script syntax error, not arbitrary script execution or a protected security effect; those promotions were not accepted into the audited security package.

## The concrete state/context gap

The final 17-claim HTML bundle used its 24-query allowance. It left five ordinary HTML claims unresolved for unread renderer/configuration evidence in that conversation. Provenance narrows the explanation:

- Transfer, OTP and dashboard application files had already been delivered completely in other native conversations. Their deciding source was available; it was not carried into this investigation.
- The two crypto usernames shared another application whose setup/header had not been delivered previously. These needed a small new read, not merely remembered facts.
- Two software-integrity claims shared one route and JavaScript string sink. Their application and template source had already been read; their remaining question was parsing/security effect, not missing renderer setup.

Thus this is partly lost evidence continuity and partly evidence allocation within a mixed bundle. It is not proof that all unresolved claims should be dismissed or all categories moved to workspace.

Native source delivery covered 79 files and 145 file/conversation pairs. Verified physical-line delivery was 7,948 unique lines and 12,709 summed unique lines across conversations, or 1.599× cross-conversation line repetition before history replay. This deduplicates within a conversation and excludes navigation previews, guidance and summaries; it is not the old Juice Shop repetition metric or an estimate of source tokens inside history.

Stable wire hashes stayed unchanged within each of the 28 native conversations. They differed between bundles; this is not one universal schema. All 80 native and 10 workspace local schema checks passed. Passing schema/source checks did not prevent weak semantic promotions in the follow-up.

## Failures and recovery

There were zero provider retries, zero unknown receipts and zero schema rejections. The native pass completed normally. After all ten follow-up calls and draft updates, my harness failed while copying a finalized response because its output directory did not exist. The initial completion/failure record is preserved.

An offline export recovery reused the already-finalized bundle, assembled its response and ran the native report over all seven claims. It blocked any reviewer invocation and made **zero additional model calls**. An initial offline recovery attempt also discovered that finalization is not idempotent at an existing directory; the successful recovery reused that result instead of deleting or overwriting it. Neither issue was a model/account failure or a reason to rerun the reviews.

## Practical direction and stop decision

1. **Keep the current native-first, cache-aware profile.** SQL and other complete local contracts close cheaply; relationship reviews can inspect identity provenance without exhaustive caller discovery. This application does not justify discarding it or promoting universal workspace review.
2. **Make evidence completion and impact review the next narrow controller improvements.** Before reinvestigating an “unread available configuration” blocker, retrieve source/version-bound evidence for that actual implementation and caller-compatible work item. Use selective workspace grouping where the deciding relationship is shared. Separately require a demonstrated protected security effect before promoting an encoding/UI defect. A source receipt or a confident second model answer is insufficient.

The existing evidence API was sufficient for this manual prototype. Do not add a generic “remember this app is safe” fact or another mandatory reviewer pass. A future automatic evidence-selection change should be replayed on these seven cases and clean controls before another full-app run. Its success criteria should include correct scope and total package price, not merely seven closed rows.

Stop this experiment here. Preserve both promising modes, these specific limitations and the remaining questions. No product prompt was retuned to this app, no new full-app tournament was launched, and no live testing is needed to support these source observations.
