## What this does not prove

The operation spans and claim-to-operation mapping were selected manually and
given to the AI. The deterministic planner started from inventory anchors. This
is an assisted capability diagnostic, not a controlled demonstration that an
automatic AI planner discovers better groups from equivalent raw inputs. Human
selection and verification labor is unmeasured. All three AI calls and two lookup
batches are part of the cost; a three-call source-assisted pass is not a cheap
one-shot metadata pass merely because its final output is short.

Ten deterministic work items versus six mixed research containers is not four
saved model calls. The two per-application packet batches already fit the native
20-review default. A capable reviewer could identify the same relationships
while reviewing those batches. No subsequent vulnerability-review calls were
run, so avoided deciding turns and preserved finding status remain untested.

The current workspace can store the source/questions, but the existing strict
same-registration grouping planner does not admit these cross-operation
dependency relationships automatically. This result does not justify relaxing
caller checks or converting every unsupported route into a global auth review.
