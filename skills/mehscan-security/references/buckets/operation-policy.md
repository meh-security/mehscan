# Operation policy

Use the bundle's named operation and invariant. Establish its sensitive
effect and the relevant producer, policy or control before assigning a
weakness. A rule or API name can be an observation without a reportable
relationship.

For logging and authentication, distinguish an executable exposure from
ordinary syntax or API inventory. For an explicit policy, check the exact
branch and whether denial stops the effect. If supplied facts affirmatively
show that the named relationship cannot occur, close that review as
`not_issue` without making claims about the wider component.

When a comparison only records telemetry and calls `next()`, follow the
registered handlers to the protected effect. A repository behavior test that
reaches the effect with the failed or missing condition can settle the question.
For a route handler, inspect earlier `app.use` mounts on every matching path
prefix before calling a request field caller-controlled; an upstream identity
middleware can overwrite it even when the exact route declaration does not
repeat that middleware.
