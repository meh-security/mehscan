# Path selection and containment review

Use for a claimed root/filename guarantee whose outcome depends on composed
transforms, platform syntax or a guard's actual applicability. Ordinary fixed or
operator-selected local work does not need a new containment investigation.

## Bind the proof to the selected effect

Identify the promised root, selected operand, actual path API and supported
platform. Follow the value through normalization, prefix removal, joining,
resolution and the read/write/delete. A check on an earlier representation does
not constrain a later transform that can reintroduce a root or change authority.
Read both operands for copy/move; a destination guard does not protect its source.

Test the proposed rejection with a concrete source-consistent path shape. A
string prefix can accept a sibling directory; a component-aware prefix or
relative-path check has different semantics. An absolute HTTP pathname does not
prove that the final filesystem operand stays relative after separators are
removed. Windows drive-rooted, drive-relative and UNC forms differ from POSIX
paths. Rejected separators alone do not exclude every rooted/prefixed value.
State API-contract reasoning as inference, with the actual binding and platform.

Do not infer that every joining API replaces its base, or that every prefix
check fails: normalization order, component-aware comparisons, complete basename
selectors and filename enumeration can settle the selected property. Check
boundary and platform counterexamples against the actual sequence. Do not launch
programs or execute repository code to test a hypothesis in worker mode.

## Check enforcement and feasible prerequisites

An earlier caller can make an unsafe helper argument infeasible. Inspect a named
applicable caller/validator when the claim depends on it; bind it to the same value
and successful branch before the effect. A later mutation check does not prevent
an earlier read. Conversely, do not report an application bypass using arguments
that its actual earlier selector cannot produce. A fixed caller is not proof for
a different delegated caller; avoid exhaustive discovery once this binding closes.

Lexical containment and symlink/rename safety are separate. State whether the
mechanism needs a readable existing target, matching suffix, link placement,
concurrent replacement or a separately privileged reader. Establish a relevant
local root guarantee or actor/authority relationship rather than assuming every
arbitrary-path utility is a restricted file service. A source-supported conditional
root violation need not prove a deployed victim; preserve an unresolved decisive
platform, guard or caller fact instead of an unqualified clean or issue.

## Finish the deciding lookup

A complete returned line range is not necessarily a complete helper. If a named
guard, parser or renderer is absent from a window, locate it with `definition` or
bounded `references` in the known file/component before reading more siblings.
A failed AST definition may return `text_lookup`; those matches locate text and
may be imports, calls, comments or alternate implementations. Follow the relevant
import and read the actual body. Do not treat a text match as dispatch proof.

Share an inspected implementation fact only across compatible callers, operands,
branches and platform conditions. Decide each claim separately. Use remaining
research for the one missing fact that can change the decision; keep unavailable
contracts distinct from available bodies left unread or budget exhaustion.
