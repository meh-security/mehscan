# Choose shared evidence by relationship

Use this when preparing a chunk or choosing its initial evidence view. Keep
exact IDs, questions, operands and independent verdicts. Raw request/binding
metadata stays on disk for finalization. A shared implementation is a research
unit; a common CWE or filename alone is not.

## Filesystem: implementation and policy

For several operations in a small coherent storage implementation, read the
whole file once. Pair it with an exact ID/operand table: root and key producer,
extension/path construction, read/write/move/cleanup effect and differing guard.
Trace actual callers to establish selectors. Reuse those source facts across
operations; a generated temporary suffix does not constrain an unsafe base.
For a large or mixed file, use constructor/path-helper/anchor-method windows
instead. Research unrelated roots and producers separately.

## HTML: binding, renderer and writers

Supply output-context and producer locations, relevant renderer/writer windows,
and the exact encoder/sanitizer/transformation identity. For templates include
relevant imports or helper registrations; for browser output include module
binding and the authored DOM/config producer when relevant. Same-named helpers
can have different behavior. Missing callable binding remains a research task.
Cover directly chained output transformations with their exact locations or
short method windows; an omitted small helper can trigger a costly global search.
Include relevant writer caller/permission/registration locations when known.
For large templates, provide binding and consumed-value/include locations first,
with static body text available on demand. A navigation map is not proof that
unshown template content has no dynamic behavior.

Check transformations in execution order and compare each actual writer, not
only the normal editor. Reuse the renderer contract while following a different
writer's trust, guard and sanitation path. Shared HTML settings do not prove
identical controls. Unknown effective policy stays precise; it does not justify
repeated deployment speculation for every site.

Use a compact candidate-writer map as navigation when available; verify the
receiver, branch and control for relevant entries. Syntax matches and truncated
reference searches do not prove complete writer coverage. Load dependency
source only when its behavior can change the decision, checking the exact version.

## Packet use

A source-bound packet may replace the initial card/sweep read when it contains
the exact selected questions, anchor IDs, operands and source. Check its coverage;
load missing facts through existing Mehscan methods. Do not reread supplied
source merely to populate a journal. Journal real follow-up queries and cite
inspected source normally. Finalize against the unchanged raw requests.

Keep packets factual and compact. Preserve useful source binding/control facts;
avoid embedding full inventory, repeated source and irrelevant schema metadata.
Expose locations when the needed producer is unresolved, rather than guessing
a relationship or packing every possible caller. There is no new CLI flag here;
ordinary bundles and targeted evidence methods remain the default input flow.
